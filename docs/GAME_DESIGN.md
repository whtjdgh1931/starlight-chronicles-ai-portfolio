## 핵심 경험

사냥터에서 얻은 장비로 캐릭터를 키우고, 준비한 장비와 익힌 조작을 보스전에서 시험합니다. 사냥에서는 장비와 성장에 필요한 자원을 모으고, 보스전에서는 공격 예고를 보고 피할 위치와 다시 공격할 때를 판단합니다.

**캐릭터 선택 → 사냥터 입장 → 경험치·장비 획득 → 장착·강화 → 솔로 또는 협동 보스전 → 보상 저장**

| 단계 | 플레이어가 하는 일 |
| --- | --- |
| 사냥 준비 | 캐릭터를 선택하고, 입장 조건을 충족하는 사냥터 난이도를 고릅니다. |
| 사냥과 성장 | 몬스터를 처치해 경험치와 드롭을 얻습니다. 의뢰를 수락하면 처치나 수집으로 목표를 진행합니다. |
| 장비 정비 | 획득한 장비의 부위와 요구 레벨을 확인하고 장착하거나 강화합니다. |
| 보스 도전 | 혼자 입장하거나 방을 만들어 함께 출정합니다. 예고된 범위와 투사체 경로를 보고 회피합니다. |
| 보상과 다음 도전 | 전투 결과에 따라 개인 보상을 받고, 캐릭터 상태를 저장해 다음 플레이로 이어갑니다. |

## 주요 게임 규칙

- **성장과 획득.** 레벨이 오르면 기본 능력치가 증가합니다. 바닥에 드롭이 겹쳐 있을 때는 현재 받을 수 있는 가까운 아이템부터 획득합니다. 받을 수 없는 아이템은 필드에 남겨, 장비 칸이 가득 차도 골드나 다른 종류의 아이템을 주울 수 있게 했습니다.
- **장착과 강화.** 요구 레벨과 장착 부위가 맞아야 장착할 수 있습니다. 가방에 빈칸이 없어 장비를 해제할 수 없다면 기존 장착 상태를 유지합니다. 장착 중인 장비를 강화하면 결과가 캐릭터 능력치에 반영됩니다.
- **보스 공격.** 근접 베기는 타격 범위를, 부채꼴 투사체는 발사 경로를 먼저 표시합니다. 최종 예고에서 확정한 발사점과 방향을 실제 투사체에 함께 사용해, 플레이어가 예고를 기준으로 회피할 수 있게 했습니다.
- **협동 전투와 보상.** 모든 참가자의 씬 준비가 끝난 뒤 전투를 시작합니다. 보스 체력과 피해는 서버 기준으로 처리하고, 부활 기회는 참가자가 공유합니다. 개인 보상 저장이 실패하면 같은 전투 결과로 저장을 다시 시도하며, 보상을 중복 지급하지 않도록 구성했습니다.

## 개발하면서 확장한 설계

| 설계에서 정한 기준 | 현재 구현에 반영한 내용 |
| --- | --- |
| 사냥 중 얻은 장비를 바로 비교하고 성장에 활용한다. | 장착 조건과 가방 공간을 먼저 확인하고, 장비가 바뀌면 능력치와 외형에 반영합니다. 7월 부록에 있던 장착·강화 규칙을 유지했습니다. |
| 보스 예고가 회피 판단의 근거가 된다. | 부채꼴 공격의 최종 예고와 실제 발사가 같은 경로 정보를 사용합니다. |
| 협동 플레이에서 보이는 반응과 전투 판정의 역할을 정한다. | 참가자의 기본 공격 입력에는 본인 화면에서 준비 자세를 먼저 표시하고, 실제 공격과 피해는 서버가 확정합니다. |
| 보상을 받은 상태로 다음 플레이를 이어갈 수 있어야 한다. | 전투 결과 수신과 캐릭터 저장을 분리하고, 저장 재시도와 파일 손상 시 백업 복구를 지원합니다. |

## 기획을 구현으로 옮긴 예시

퀘스트 보상과 저장을 확인하려면 사냥과 수집으로 같은 상황을 반복해서 만들어야 했습니다. 어떤 조건을 준비하고, 어떤 요청을 실행하며, 어떤 결과를 비교할지 먼저 나눴습니다. 보상은 한 번만 지급되고 저장만 다시 시도할 수 있어야 한다는 기준을 세운 뒤, Codex를 활용해 기존 게임 API를 호출하는 Unity Inspector 도구로 구현했습니다. [AI 활용 사례와 구현 코드](../README.md#ai-활용-사례)
