## 게임 방향과 플레이 흐름

클래식 횡스크롤 RPG의 이동과 성장 감각을 짧은 PC 플레이에 담는 것이 목표였습니다. 마을과 사냥터는 싱글 플레이로 진행하고, 함께 패턴을 피하고 공격할 타이밍을 맞추는 재미가 큰 보스전에서 협동을 선택할 수 있게 기획했습니다. 조작 직후의 반응, 읽을 수 있는 공격 예고, 수치와 외형으로 확인하는 성장을 주요 기준으로 삼았습니다.

**마을에서 준비 → 포털로 사냥터 이동 → 처치와 드롭 획득 → 장비 비교·장착·강화 → 보스 도전 → 보상 정산과 재도전**

| 영역 | 상세 기획서의 설계 |
| --- | --- |
| 직업과 전투 | 전사는 근접과 생존, 궁수는 거리 유지와 지속 사격, 마법사는 이동과 범위 제어에 초점을 맞췄습니다. 공격을 준비·활성·회복 구간으로 나누고, 활성 구간에 피해 판정을 적용하도록 설계했습니다. |
| 몬스터와 보스 | 일반 몬스터는 순찰·추적·공격·피격·사망 상태를 전환합니다. 보스는 예고를 보고 대응하는 전투를 목표로 했으며, 1페이즈에서 회피 타이밍을 익히고 2페이즈에서 협동 대응을 요구하도록 기획했습니다. |
| 화면과 조작 | HUD에는 HP·MP·경험치와 스킬 상태를 표시하고, 인벤토리와 장비 화면에서는 장착 조건과 수치를 비교할 수 있게 했습니다. 위험 예고는 색과 형태 등 여러 신호로 전달하도록 계획했습니다. |
| 협동과 결과 | 방 생성·참가 → 준비 확인 → 공동 로딩 → 전투 → 결과 정산 순서입니다. 호스트가 보스 상태와 피해를 확정하고, 같은 결과 ID를 한 번만 처리하도록 설계했습니다. |
| 데이터와 저장 | 아이템 ID·드롭 확률·강화 확률·포털 참조의 유효성을 검사하도록 계획했습니다. 저장은 임시 파일을 거쳐 교체하고, 본 파일을 읽을 수 없으면 정상 백업으로 복구하는 방향을 정했습니다. |

## v4.1에서 구체화한 규칙

| 영역 | 개정 내용 |
| --- | --- |
| 레벨업 | 초과 경험치의 90%를 다음 레벨로 이월하며, 여러 레벨이 한 번에 오르면 단계마다 적용합니다. 레벨업 시 기본 능력치가 고정량 증가하고 HP·MP가 새 최대치까지 회복됩니다. |
| 드롭 줍기 | 수동 입력 한 번에 실제로 받을 수 있는 가장 가까운 드롭 하나를 줍습니다. 장비 칸이 가득 차도 골드나 다른 탭의 아이템을 주울 수 있고, 받을 수 없는 아이템은 필드에 남습니다. |
| 장착과 강화 | 호환되는 부위에 장착하고, 가방에 공간이 있을 때 해제합니다. 강화 슬롯에는 대상만 등록하고 장비의 위치는 유지합니다. 장착 중인 장비의 강화 결과는 능력치와 외형에 반영하고, 파괴되면 자동 해제합니다. |
| 자석과 펫 | 자석 스킬과 펫이 같은 탐색 기반을 쓰도록 하고, 아이템이 날아가는 위치와 보상을 받는 대상을 구분했습니다. 이동 중 가방이 가득 차면 드롭을 필드 상태로 복구하도록 설계했습니다. 펫 자동 획득과 저장은 MVP 이후 범위였습니다. |

## 당시 제작 범위와 현재 프로젝트

당시 MVP는 **전사 1직업으로 마을 → 사냥 → 장비 성장 → 싱글·2인 보스전**을 완주하고, 저장·복구까지 확인하는 범위였습니다. 3직업과 직업별 4개 스킬, 최대 4인 보스전, 잠재능력은 이후 확장 목표였습니다. 플레이 진행, 저장 복구, 보상 중복 방지, 1080p 60fps는 당시 문서에서 정한 수용 기준입니다.

현재 Starlight Chronicles는 **Unity Netcode for GameObjects, Lobby, Relay**로 협동 보스전을 구현했습니다. 통합본에 적힌 **Photon Fusion Host Mode**는 7월 당시 계획입니다. 현재 보스전에서는 근접 타격 범위와 부채꼴 투사체 경로를 예고하고, 전투 결과 수신과 개인 저장을 분리해 저장만 재시도할 수 있게 했습니다. [현재 구현과 검증 범위](../README.md#핵심-게임-구현)
